## Этап 1: что реализовано

| Объект | ID | Что умеет |
|---|---|---|
| Печатная плата (предмет) | `projectrebirth:circuit_board` | компонент; рецепт: 2 редстоуна + золотой самородок + 3 медных слитка |
| Сборочная станция (блок) | `projectrebirth:assembly_station` | ставится лицом к игроку, добывается киркой, выпадает сама; ПКМ: сообщение «пока не работает». Рецепт: железо + 2 платы + верстак |
| Базовое роботизированное тело (сущность + предмет) | `projectrebirth:basic_robot_body` | см. ниже |

Базовое тело:
- предмет ставит тело на блок (лицом к игроку), предмет расходуется; если места нет, тело не ставится и предмет остаётся;
- ПКМ по телу: на экране целостность (здоровье) «текущая / максимум» + анимация отклика;
- Shift + ПКМ: тело упаковывается обратно в предмет; урон сохраняется в предмете (видно в подсказке), лечения через упаковку нет;
- тело не исчезает само (не деспавнится), не привязывается поводком;
- максимальная целостность и броня берутся из конфига и применяются к уже существующим телам при загрузке;
- рецепт: плата + 4 железных слитка + блок редстоуна;
- при уничтожении пока ничего не выпадает (будет решено на этапе 2).

Конфиг баланса: `config/projectrebirth-server.toml` (серверный; в NeoForge 1.21.1 он лежит в общей папке `config`),
секция `[bodies.basic_robot_body]`: `maxHealth`, `armor`.

### Архитектура тел

Одна общая логика на все классы тел:
- `bodies/BodyClass`: перечень классов (сейчас только `BASIC_ROBOT`) и значения по умолчанию;
- `bodies/ArtificialBodyEntity`, `ArtificialBodyItem`: общие для всех классов;
- `BodyEntities`, `BodyItems`, `RebirthConfig`: регистрируют тип сущности, предмет и секцию конфига для каждого класса в цикле;
- `client/render/ArtificialBodyRenderer`: один рендерер, файлы модели ищет по id класса.

Добавить новый класс = строка в `BodyClass` + модель/текстура/анимация + переводы + рецепт.

## Что реально проверено

- `.\gradlew build`: собирается без ошибок.
- `.\gradlew runGameTestServer`: **4 из 4 автотестов прошли** (на сервере):
  1. предмет ставит тело и расходуется, у нового тела полная целостность;
  2. упаковка даёт ровно один предмет даже при двойном нажатии, урон сохраняется;
  3. повреждённое тело после установки остаётся повреждённым;
  4. без свободного места тело не ставится, предмет не тратится.
- Выделенный сервер + клиент, подключённый к нему (по логам и снимкам окна игры):
  - модель тела, текстура, блок станции и иконки трёх предметов отображаются, ошибок в логах нет;
  - **анимация простоя проверена**: по серии снимков голова поворачивается влево/вправо, антенна качается
    (снимок: `docs/screenshots/stage1_body_idle.png`);
  - тело пережило два перезапуска сервера; урон (14/20) сохранился;
  - изменение `maxHealth` в конфиге на 30 применилось к уже существующему телу после перезапуска.

## Что НЕ проверено

- Анимация отклика (`animation.body.interact`) в игре: я не могу нажимать кнопки в игре, а команды её не вызывают.
  Серверная часть (ПКМ, упаковка) проверена автотестами, но визуально кивок и поднятая рука не видены.
- Ручные действия игрока в настоящем клиенте: ПКМ/Shift+ПКМ по телу, установка тела, сообщения на экране, подсказки и русские тексты.
- Рецепты в интерфейсе верстака (сервер загрузил их без ошибок, но крафт руками не проверялся).
- Одиночная игра (проверялись выделенный сервер и клиент, подключённый к нему).

## Структура кода

- `ProjectRebirth`: общая точка входа (клиент и сервер), регистрации и конфиг.
- `client/ProjectRebirthClient`: клиентская точка входа (на сервере не загружается), рендереры.
- `core/ModCreativeTabs`: вкладка «Project: Rebirth» в творческом режиме.
- `config/RebirthConfig`: серверный конфиг баланса.
- `bodies/*`: искусственные тела.
- `technology/*`: плата и сборочная станция.
- `gametest/BodyGameTests`: автотесты; площадка `data/projectrebirth/structure/floor_3x3.nbt`.
